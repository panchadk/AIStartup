1. Why build it from scratch?

In Module 1, one line, loss.backward(), computed every gradient for you. That is called autograd. It is wonderful, but it hides how learning works.

In this module you write the forward pass, the loss, and backpropagation yourself in plain NumPy, then check them against PyTorch. Afterwards you will no longer treat backward() as magic, and you will be much better at debugging models that do not learn.

The data is three interleaved spirals, 100 points each. A straight line cannot separate them, so the network has to learn curved boundaries.

2. A neuron and a layer

A neuron multiplies each input by a weight, adds the results and a bias, and then applies a nonlinear function.

A layer is many neurons computed at once with a matrix multiplication. With N examples and 2 inputs, the shapes are:

X  (N, 2)   @   W1 (2, 100)   +   b1 (100,)   =   z1 (N, 100)

The rule: the inner sizes must match (2 and 2), and the result takes the outer sizes (N and 100). The bias is added to every row.

3. Why we need nonlinearity

Suppose a network has two layers but no nonlinearity between them. Then the output is W2 (W1 x), which equals (W2 W1) x. That is just one layer, so adding layers gains nothing. It can only draw straight lines.

ReLU is max(0, z): negative values become 0 and positive values pass through. The hidden layer has 100 ReLU units, each contributing one bend. Together they can bend a boundary around the spirals. A linear model on the same data scores only about 54%, while this network reaches about 99%.

4. Softmax and cross-entropy

The last layer outputs 3 raw scores (logits), one per spiral. Softmax turns scores into probabilities that are positive and add up to 1.

Example with logits [2.0, 1.0, 0.1]: take exp of each (7.39, 2.72, 1.11), then divide by the total (11.21). The probabilities are about 0.659, 0.242, 0.099.

If class 0 is the correct one, the cross-entropy loss is minus the log of its probability: −ln(0.659) = 0.417. The loss is the average of this over all N examples.

Numerical stability trick: exp of a large number overflows. Subtract the largest score in each row before taking exp. The probabilities do not change, but the numbers stay small. Your self-check tests this directly.
A lovely fact: for softmax with cross-entropy, the gradient of the loss with respect to the scores is simply probs with 1 subtracted at the correct class, divided by N. This is where backpropagation starts.

5. Backpropagation

Backpropagation is just the chain rule applied from the loss back to every weight. A tiny example: if z = 3x and L = z², then the effect of x on L is the effect of x on z times the effect of z on L:

dL/dx = dL/dz * dz/dx = (2z) * 3 = 6z

Check with x = 2:  z = 6,  L = 36,  dL/dx = 6 * 6 = 36
Directly:          L = 9x^2,  dL/dx = 18x = 36   (matches)

A network is a longer chain. Work from right to left, multiplying local gradients as you go:

  1. dlogits = (probs − onehot) / N. The starting point.
  2. dW2 = h.T @ dlogits and db2 = the sum of dlogits over examples.
  3. dh = dlogits @ W2.T. Send the gradient back through the second layer.
  4. dz1 = dh, but 0 wherever z1 ≤ 0. This is the gradient of ReLU. Where ReLU output 0, no signal passes.
  5. dW1 = X.T @ dz1 and db1 = the sum of dz1.
Shape rule that catches most bugs: every gradient has exactly the same shape as the parameter it belongs to. If W1 is (2, 100), then dW1 must be (2, 100). If the shapes do not match, your transposes are wrong.

Biases are shared by every example, so their gradient is a sum over the batch. That is why db1 and db2 use a sum.

6. Gradient descent

A gradient says which way is uphill. To lower the loss, step the opposite way:

w  =  w  -  learning_rate * gradient

The learning rate sets the step size. It is one of the most important numbers in training.

  • Too small: it works but takes very many steps.
  • About right: a steady descent to the bottom.
  • Too large: it jumps across the valley and can end higher than it started, so the loss goes up or becomes nan.

This module uses all 300 points for every step (full-batch). Module 3 switches to mini-batches. In the stretch challenge you add momentum: a running velocity that smooths the steps.

7. Gradient checking

How do you know your backward pass is right? Test it. Nudge one weight up and down by a tiny amount e, and see how the loss changes. That slope is a numerical gradient:

(loss(w + e) - loss(w - e)) / (2 * e)
  • Compare with a relative error: norm(a - n) / (norm(a) + norm(n)). Below 1e-6 means your gradients are correct.
  • Use float64. With float32 the numbers are too imprecise for this test.
  • This is slow, because it needs two forward passes per weight. So you only use it for debugging, on a tiny network, exactly as the notebook does.
  • The notebook then compares with PyTorch autograd as a second opinion.
Reading a failure: if the check fails only for W1 and b1 but passes for W2 and b2, the bug is in the part of backprop that runs after it reaches dh: the ReLU gradient or the first layer's formulas.

8. Key terms

TermPlain meaning
Forward passComputing the output from the input, layer by layer
Backward passComputing gradients from the loss back to every weight
Chain ruleThe effect of a chain of steps is the product of each step's effect
ReLUmax(0, z): sets negatives to 0, adding a bend
SoftmaxTurns scores into probabilities that add up to 1
Cross-entropyMinus the log of the probability given to the correct class
Gradient checkVerifying hand-written gradients against numerical ones
MomentumA running velocity that smooths gradient descent

9. Common pitfalls

  • Forgetting to divide by N in dlogits, so every gradient is N times too big.
  • Leaving out the ReLU mask, so only W1 and b1 fail the check.
  • Wrong transposes. Use the shape rule: a gradient matches its parameter.
  • Forgetting to subtract the row maximum in softmax, which gives nan for large scores.
  • Using += instead of -= in the update, so the loss rises.
  • Using float32 in the gradient check, then chasing an error that is only rounding.

10. Check yourself

Try each question first, then open the answer.

Question 1: X has shape (300, 2), W1 has shape (2, 100), and b1 has shape (100,). What is the shape of X @ W1 + b1?

(300, 100). The inner sizes (2 and 2) match and disappear, and the bias is added to each of the 300 rows.

Question 2: Why is dlogits divided by N?

The loss is the mean over N examples, so each example contributes only 1/N of the gradient. Forgetting this makes every gradient N times too large.

Question 3: The gradient check passes for W2 and b2 but fails for W1 and b1. Where is the bug?

In the earlier layers of backprop, after the gradient reaches dh: most likely the ReLU mask (dz1 = dh * (z1 > 0)) or the formula for dW1 and db1. The output layer's gradients are fine.
