Module 4: Fix the broken models

Click the button to open the interactive notebook in Google Colab. Then choose File, Save a copy in Drive, and work in your own copy. No GPU is needed: every case runs in seconds on the CPU.

Lecture notes: read the illustrated notes (about 20 minutes, with diagrams). Read them first, or return to them when you are stuck.

Notes (about 10 minutes)

  • Debug in order: data first, then the loss and labels, then the model, then the optimizer. Stop at the first thing that looks wrong.
  • Overfit one batch: a correct model and loop can drive the loss on a single small batch to nearly zero. If it cannot, something basic is broken.
  • Common bugs: data leakage between train and test, the wrong loss for the task, forgetting model.eval() when evaluating, not shuffling, and a learning rate that is far too high or too low.
  • Check shapes and value ranges at every stage. Print one batch and look at it.
  • Compare against a trivial baseline. If you cannot beat it, something is wrong.
  • The loss tells you more than the accuracy. A 3-class model that guesses has a loss of about 1.1 (the natural log of 3).

Exercises (all in the notebook)

  1. Case 1: leakage. A test score that is too good. Find why the test set is not honest and fix the split.
  2. Case 2: stuck loss. Accuracy looks fine but the loss stalls. Find the loss and output mismatch.
  3. Case 3: huge loss. The loss starts in the hundreds. Use a learning rate range test to fix it.
  4. Case 4: sorted data. The model favours the last class it saw. Find the order bug.
  5. Case 5: eval mode. The same model gives different scores each time. Fix the evaluation function.
  6. Write a root cause in one line for each case: what was really wrong, not just what you changed.
  7. Write your own debugging checklist with at least 8 items.
  8. Stretch: plant a realistic bug in a pipeline and write the symptom story for a classmate to solve.

The five cases are in one notebook, and you can do them in any order.
