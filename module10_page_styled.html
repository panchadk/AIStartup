Module 10: Deploy and measure

Project: take a trained model out of the notebook and turn it into a service: an API that other programs can call, and a web page that anyone can use. Then measure how fast and how expensive it is, and write the one-page idea for your capstone. Time: about 8 hours core, plus about 4 hours for the stretch challenge.

Notes (about 10 minutes)

  • A model in a notebook is not a product. Wrap it in an API (FastAPI) so that any application can call it.
  • Gradio or Streamlit give a quick web page, and Hugging Face Spaces can host it for free with a public address.
  • Measure latency with percentiles, not just the average. The 95th percentile (p95) is the time under which 95% of requests finish.
  • Cost per request depends on how long a request takes, the price of the machine, and how busy the machine is.
  • Reduce cost and latency with a smaller model, caching repeated requests, batching, and shorter inputs.
  • Log what you need to monitor the service, but never the private content of the requests.

Exercises (all in the notebook)

  1. Save and load the model and write a predict function.
  2. Privacy-safe logging. Write make_log_record().
  3. The API. Write create_app() with /health and /predict, and reject bad requests.
  4. Run it as a server and call it with real requests.
  5. Measure latency over 50 requests. Write summarize_latencies() with the average, p50, p95 and p99.
  6. Cost. Write the capacity, cost per request and monthly cost formulas.
  7. Deploy to Hugging Face Spaces and check that the public URL works for someone else.
  8. Write your capstone idea: problem, user, why deep learning, data, success metric, risks.
  9. Stretch: add caching and a load test, and measure again.
