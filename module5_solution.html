Step 2: stratified split

Split each class separately, so every class appears in the same proportions in all three splits. With 150 images, a plain random split could by bad luck leave a class almost missing from the test set.

def stratified_split(labels, val_frac=0.15, test_frac=0.15, seed=0):
    rng = np.random.default_rng(seed)
    labels = np.asarray(labels)
    train_idx, val_idx, test_idx = [], [], []
    for c in np.unique(labels):
        idx = np.where(labels == c)[0]
        rng.shuffle(idx)
        n_test = int(round(len(idx) * test_frac))
        n_val = int(round(len(idx) * val_frac))
        test_idx += idx[:n_test].tolist()
        val_idx += idx[n_test:n_test + n_val].tolist()
        train_idx += idx[n_test + n_val:].tolist()
    return train_idx, val_idx, test_idx

Step 3: transforms

Training gets random augmentation. Evaluation gets only a deterministic resize and centre crop. Both end with the same ToTensor and Normalize using the ImageNet statistics, because the pretrained network was trained on images normalized that way.

imagenet_mean = [0.485, 0.456, 0.406]
imagenet_std = [0.229, 0.224, 0.225]

train_tfms = transforms.Compose([

eval_tfms = transforms.Compose([

])

Step 5: the pretrained model with a new head

The order matters: freeze everything first, then replace the head. A layer you create after freezing is trainable by default, so the head is the only trainable part. Doing it the other way round freezes the new head as well, and nothing would learn.

def build_finetune_model(num_classes, freeze_backbone=True):
    model = models.resnet18(weights=models.ResNet18_Weights.DEFAULT)
    if freeze_backbone:
        for p in model.parameters():
            p.requires_grad = False
    model.fc = nn.Linear(model.fc.in_features, num_classes)
    return model.to(device)

Step 6: unfreeze

After the head has learned something sensible, make everything trainable again and continue with a much smaller learning rate (1e-4 instead of 1e-3). Remember to build a new optimizer after unfreezing, because the old one only knew about the head's parameters.

def unfreeze(model):
    for p in model.parameters():
        p.requires_grad = True

Step 7: confusion matrix

Rows are the true classes and columns the predicted classes. Each example adds 1 to one cell, so the whole matrix sums to the size of the test set, and the diagonal divided by the total is the accuracy.

def confusion_matrix(model, loader, num_classes):
    model.eval()
    cm = np.zeros((num_classes, num_classes), dtype=int)
    with torch.no_grad():
        for x, y in loader:
            pred = model(x.to(device)).argmax(1).cpu().numpy()
            for t, p in zip(y.numpy(), pred):
                cm[t, p] += 1
    return cm

Sample answers to the written questions

  • Worst mistakes, 3 patterns: look for repeating causes rather than single cases. Typical patterns: (1) two classes that really look alike, (2) a misleading background or lighting, such as one class mostly photographed outdoors, (3) a blurry or partly hidden object, (4) a wrong label in the dataset. Each pattern suggests a different next step: more examples of the confusing pair, more varied backgrounds, better photos, or cleaning labels.
  • Conclusion: a good answer compares the three numbers, says why pretraining helps (the backbone already knows edges and shapes, so only a small head must be learned from your few photos), and names a concrete next data-collection step. If the from-scratch model happened to do as well, say so honestly and consider that your classes may be very easy, or your test set too small to show a difference.
  • Stretch, backbone comparison: smaller models such as MobileNet are much faster and a little less accurate, which matters on a phone. Larger models such as EfficientNet or bigger ResNets are slower and sometimes more accurate. Report both numbers and choose by the product's need, not by accuracy alone.

Common mistakes and what they look like

  • Forgetting Normalize, or using different statistics: accuracy is much lower than expected, because the pretrained network sees inputs it was never trained on. The transforms self-check tests this.
  • Augmenting validation and test images: scores change from run to run and are not comparable. Only the training transforms are random.
  • Freezing after replacing the head: nothing trains, and the loss barely moves. The build self-check lists the trainable parameters.
  • Not building a new optimizer after unfreezing: the old optimizer only updates the head, so phase 2 learns almost nothing.
  • A fine-tuning learning rate that is too high (for example 1e-2): the pretrained features are destroyed, and accuracy drops below the head-only result.
  • Duplicates or near-duplicates across splits: inflated test accuracy, as in Module 4. The dataset check catches exact duplicates only, so also avoid taking many near-identical shots of the same object.
  • A shortcut in the data: for example, every photo of class A is on a white table. The model learns the table. Vary backgrounds, and look at your worst mistakes for this.
  • Trusting a tiny test set: with about 25 test images, one mistake is about 4 points. Collect more test photos before drawing conclusions.
  • Class order surprises: ImageFolder sorts classes alphabetically, so label 0 is the first folder alphabetically. Use class_names to read results.
  • Frozen backbone, but BatchNorm still updates: in training mode, a frozen backbone's BatchNorm layers keep updating their running statistics. For this module it does little harm. It is something to know about when results look odd.
