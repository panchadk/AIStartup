Before you start: choose a narrow task

Fine-tuning pays off on narrow, repeated tasks with a fixed output format: classifying messages, extracting fields into JSON, rewriting text in a house style. You need an input and an output for every example, and at least 200 examples. Put them in a file my_task.csv with two columns, input and output, and upload it. No data yet? The notebook includes a demo task (reading customer messages and answering with a JSON record).

Notes (about 10 minutes)

  • Try prompting first, with examples if needed. Fine-tune only when prompting cannot reach the quality, format, speed or cost you need.
  • Fine-tuning is best for a consistent format, tone, or narrow task. It is a poor way to add facts that change: use RAG for those.
  • LoRA freezes the original weights and trains small adapter matrices, so it fits on one modest GPU and produces a tiny adapter file.
  • Train on answers only: mark the prompt tokens with the label -100 so that the loss ignores them.
  • Data quality matters more than quantity. A few hundred clean examples can be enough for a narrow task.
  • Compare options on three axes: quality, cost per request, and latency. Include the one-time training cost and work out the break-even point.

Exercises (all in the notebook)

  1. Build the dataset and split it into train, validation and test.
  2. Scoring. Write normalize_output() and is_correct() so harmless differences are not counted as errors.
  3. Measurement. Write evaluate_system(), which reports quality, format validity, latency and tokens.
  4. Baselines. Evaluate the small model untuned, then write build_fewshot_prompt() and evaluate a larger prompted model.
  5. Training data. Write to_chat() and tokenize_example() with the prompt masked out.
  6. LoRA. Write make_lora_model(), then fine-tune and evaluate.
  7. Costs. Write the API cost, GPU cost and break-even formulas, and build the comparison table.
  8. Recommend. Write a recommendation that uses your numbers for quality, cost and latency.
  9. Stretch: plot quality against the number of training examples.
