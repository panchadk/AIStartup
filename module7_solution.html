Step 3: the prompt

The rules go in the system message. The evidence comes before the question in the user message, and every passage has a number so that the model can cite it. The exact abstain sentence appears in the rules so that the model knows what to say, and so that your code can recognize it.

ABSTAIN = "I don't know based on the documents."

def build_prompt(question, passages):
    system = ("You answer questions using ONLY the numbered passages provided by the user. "
              "Cite the passages you used with their numbers in square brackets, like [1] or [2]. "
              f"If the passages do not contain the answer, reply exactly: {ABSTAIN} "
              "Do not use outside knowledge. Keep the answer short.")
    blocks = [f"[{i}] (source: {p['source']})\n{p['text']}" for i, p in enumerate(passages, 1)]
    user = "\n\n".join(blocks) + f"\n\nQUESTION: {question}"
    return system, user

Step 4: citations and the full answer

A model may write [2] or [1, 3], and sometimes invents a number that does not exist, so the extraction accepts lists and ignores numbers out of range. In answer(), the gate comes before the model call, which saves the cost of the call and removes one chance to hallucinate. An abstention carries no citations, even if the text contains a bracket.

def extract_citations(text, passages):
    cited, seen = [], set()
    for group in re.findall(r"\[([\d,\s]+)\]", text):
        for part in group.split(","):
            part = part.strip()
            if part.isdigit():
                n = int(part)
                if 1 <= n <= len(passages) and n not in seen:
                    seen.add(n); cited.append(passages[n - 1])
    return cited

def answer(question, k=4, min_score=0.0):
    passages = retrieve(question, k)
    if not passages or passages[0]["score"] < min_score:
        return {"question": question, "answer": ABSTAIN, "abstained": True, "citations": [], "passages": passages,
                "input_tokens": 0, "output_tokens": 0}
    system, user = build_prompt(question, passages)
    reply = generate(system, user)
    text = reply["text"]
    abstained = text.strip().lower().startswith("i don't know")
    return {"question": question, "answer": text, "abstained": abstained,
            "citations": [] if abstained else extract_citations(text, passages),
            "passages": passages, "input_tokens": reply["input_tokens"], "output_tokens": reply["output_tokens"]}

Step 7: grade

An unanswerable question is handled correctly only if the chatbot abstains. An answerable one needs two things at once: it must answer, and the passage it cites must contain the gold phrase. Checking the cited passages (not all retrieved ones) is what makes citations meaningful: an answer that cites an unrelated passage is wrong even if the right passage was retrieved.

def grade(item, result):
    if not item["answerable"]:
        return bool(result["abstained"])
    if result["abstained"]:
        return False
    return any(g.lower() in c["text"].lower() for c in result["citations"] for g in item["gold"])

Prices are per million tokens, so divide the token counts by a million before multiplying.

def cost_estimate(input_tokens, output_tokens, price_in_per_m, price_out_per_m):

If your accuracy is below 80%

Print the FAIL lines and, for each failed question, look at the retrieved passages with retrieve(question). Then decide which of the four failure points you have:

  1. Retrieval miss (the right passage is not among the retrieved ones): raise k, improve your chunking from Module 6, or check that the gold phrase really is in a chunk. No prompt can fix this.
  2. Ignored evidence (the right passage is there, but the answer is wrong or from the model's own memory): make the prompt stricter, put the rules in both the system message and at the end of the user message, or use a larger model. Small open models often ignore instructions; the 3-billion-parameter version of the model, or a hosted one, follows them much better.
  3. Missing or wrong citation (the answer is right, but no [n], or the wrong one): add an example of the expected format to the system message, for example "Example: The module sleeps for a time. [2]".
  4. Answers when it should not (an unanswerable question gets an answer): raise MIN_SCORE, strengthen the abstain rule, and check that your unanswerable questions really are unanswerable.

Also check your test set. A gold phrase that is too narrow makes correct answers count as wrong.

Sample answers to the written questions

  • Answer without retrieval: the model answers generically, from what it learned in training. It has no way to point to your documents, and it may state something false with confidence. That is exactly what RAG fixes.
  • Retrieval or generation? A good diagnosis looks at the retrieved passages first. If the right passage was there and the answer is still wrong, it is a generation problem. If it was not there, it is a retrieval problem, and the fix is in Module 6's territory, not in the prompt.
  • What cuts the cost most? Because the retrieved passages dominate the input, reducing k or using shorter chunks cuts the most, and a cheaper or smaller model cuts the price per token. The min_score gate saves whole calls for questions the documents cannot answer. Going from k=4 to k=2 roughly halves the input tokens, at some risk to accuracy: say what you measured.

Common mistakes and what they look like

  • A prompt that says "use the passages" but not "only": the model mixes in its own knowledge, so unanswerable questions get confident answers.
  • Not telling the model the exact abstain sentence: it rephrases ("Sorry, I could not find that"), and your code does not recognize the abstention.
  • Parsing only [2]: a citation written as [1, 3] is lost, so a correct answer looks uncited.
  • Trusting citation numbers blindly: models sometimes cite [7] when only 4 passages exist. Ignore numbers out of range.
  • Grading with all retrieved passages instead of the cited ones: the score looks better than the chatbot really is.
  • Embedding the question with a different model than the documents: retrieval looks random. Use the same embedding model as Module 6.
  • Putting an API key in the notebook: anyone who sees your repo can use (and bill) your key. Use the Secrets panel and keep keys out of Git.
  • Only testing questions the documents can answer: the chatbot looks perfect until a real user asks something outside them.
