Step 2 question: what does torch.Size([64, 1, 28, 28]) mean?

It is the shape of one batch of images: 64 images in the batch, 1 channel (grayscale; a color image would have 3), each 28 pixels tall and 28 pixels wide. The labels are shaped [64], one class number from 0 to 9 per image.

Step 6: evaluate

Switch to evaluation mode, turn off gradient tracking, count correct predictions across all batches, and divide by the total. Expect roughly 85% to 88%.

def evaluate(dl):
    model.eval()
    correct, total = 0, 0
    with torch.no_grad():
        for x, y in dl:
            x, y = x.to(device), y.to(device)
            correct += (model(x).argmax(1) == y).sum().item()
            total += y.size(0)
    return correct / total if total else 0.0

Common mistakes and what they look like

  • Forgot optimizer.zero_grad(): the loss jumps around or gets worse, because gradients pile up from earlier batches.
  • Wrong order of the five steps: the loss does not go down. The order is forward, loss, zero_grad, backward, step.
  • Forgot .to(device) on x and y: an error saying tensors are on different devices (cuda and cpu).
  • Wrong layer sizes: an error like "mat1 and mat2 shapes cannot be multiplied". The first Linear takes 784 inputs and the last gives 10 outputs.
  • Added a softmax before CrossEntropyLoss: accuracy is lower than expected. The loss already includes it, so give it the raw outputs.
  • Forgot model.eval() or torch.no_grad() when evaluating: slower and uses more memory. It matters much more once models have dropout or batch norm.
  • Accuracy below 85%: check that you trained for all 5 epochs and that evaluate divides by the total number of test images, not the number of batches.
