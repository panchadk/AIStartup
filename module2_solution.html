Step 1 question: why will a linear model struggle on the spirals?

A linear model can only draw straight decision boundaries. The three spirals are interleaved, so any straight line puts points of different classes on the same side. It scores about 54%, a little better than guessing. The hidden layer with ReLU lets the network bend the boundary and reach about 99%.

Step 2: forward pass

Hidden pre-activation, ReLU, then output scores. The cache keeps the values the backward pass needs.

def forward(params, X):
    z1 = X @ params["W1"] + params["b1"]
    h = np.maximum(0, z1)
    logits = h @ params["W2"] + params["b2"]
    return logits, (X, z1, h)

Step 3: softmax and cross-entropy loss

Subtracting the row maximum does not change the softmax result, but it stops exp() from overflowing. The loss is the average of minus the log of the probability given to the correct class.

def softmax_cross_entropy(logits, y):
    shifted = logits - logits.max(axis=1, keepdims=True)
    exp = np.exp(shifted)
    probs = exp / exp.sum(axis=1, keepdims=True)
    loss = -np.log(probs[np.arange(len(y)), y]).mean()
    return loss, probs

Step 4: backpropagation

Work backwards with the chain rule. The first line is the key result: for softmax with cross-entropy, the gradient on the scores is simply probs minus 1 at the correct class, divided by N. The ReLU gradient is 1 where z1 > 0 and 0 elsewhere, so it acts as a mask.

def backward(params, cache, probs, y):
    X, z1, h = cache
    N = len(y)
    dlogits = probs.copy()
    dlogits[np.arange(N), y] -= 1
    dlogits /= N
    dW2 = h.T @ dlogits
    db2 = dlogits.sum(axis=0)
    dh = dlogits @ params["W2"].T
    dz1 = dh * (z1 > 0)
    dW1 = X.T @ dz1
    db1 = dz1.sum(axis=0)
    return {"W1": dW1, "b1": db1, "W2": dW2, "b2": db2}

Step 5: gradient descent loop

Only the four lines inside the loop are yours. Each parameter steps against its gradient, scaled by the learning rate.

params = init_params()
lr = 1.0
loss = None
history = []

for i in range(5000):
    logits, cache = forward(params, X)
    loss, probs = softmax_cross_entropy(logits, y)
    grads = backward(params, cache, probs, y)
    for k in params:
        params[k] -= lr * grads[k]

    if i % 500 == 0 or i == 4999:
        history.append(float(loss))
        print(f"step {i}: loss {loss:.4f}")

Stretch: momentum

Keep a velocity for each parameter. It smooths the updates and often lowers the loss faster with the same learning rate.

params = init_params()
velocity = {k: np.zeros_like(v) for k, v in params.items()}
lr, mu = 0.5, 0.9

for i in range(5000):
    logits, cache = forward(params, X)
    loss, probs = softmax_cross_entropy(logits, y)
    grads = backward(params, cache, probs, y)
    for k in params:
        velocity[k] = mu * velocity[k] - lr * grads[k]
        params[k] += velocity[k]

Common mistakes and what they look like

  • Forgot to divide by N in dlogits: the gradient check fails, and every gradient is N times too large (300 times here). Training may also blow up.
  • No ReLU mask in the backward pass (dz1 = dh): the check fails for W1 and b1 only, while W2 and b2 pass. That narrows the bug to the layers before the ReLU.
  • Wrong transpose: a shape error such as "operands could not be broadcast" or "shapes not aligned". Every gradient must have the same shape as its parameter: h.T @ dlogits for W2, X.T @ dz1 for W1.
  • Forgot to subtract the row maximum in softmax: a nan loss when scores are large. The loss self-check tests this directly.
  • Updating with += instead of -=: the loss goes up or becomes nan. Gradient descent steps against the gradient.
  • Summing instead of averaging the loss: the loss self-check (log 3 for equal scores) catches it, and the gradients no longer match.
  • Gradient check fails by a tiny amount (around 1e-4): use float64 arrays, as in the notebook. float32 is too imprecise for this check.
