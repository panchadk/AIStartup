Module 11: Capstone, build

Project: build the core of your own AI startup prototype, alone or in a team of 2 to 4. Get a thin version working from end to end, and measure it honestly. Module 12 hardens, prices and presents it. Time: about 14 hours core, plus about 6 hours for the stretch challenge.

Done when: your one-page idea is final and you have a scope list; you have a plan that fits your time and interfaces your team agreed on; an end-to-end version works on real inputs and someone outside your team can run it; and you ran your evaluation harness on it, compared it with a simple baseline, and recorded the results.

Click the button to open the workbook in Google Colab. Choose File, Save a copy in Drive, and work in your own copy with your team.

Lecture notes: read the illustrated notes (about 25 minutes, with diagrams). Read them first, or return to them when you are stuck.

Before you start

  • Your idea. Start from the one-page capstone idea you wrote in Module 10. If you have no idea you like yet, pick a small one that you can finish: a specific user, data you can really get, and a number that means "good enough".
  • Your team. Teams of 2 to 4. Agree the roles on day 1 (data and labeling, model, API and deployment, pitch and testing). Working alone is fine: you wear every hat, so write the roles down anyway.
  • Practice first. The workbook has a ready-made demo project (USE_DEMO = True) so that you can see the whole workflow once before doing it for real.

Notes (about 10 minutes)

  • Start with one user and one painful problem. A narrow product that works beats a broad one that does not.
  • Build the thinnest end-to-end version first (input, model, output, and a way to run it), then thicken the weakest part.
  • Decide build versus buy for each part: use a pretrained model or an API unless you have a clear reason to train your own.
  • Test with real users early. Five honest user tests teach more than another week of tuning.
  • In a team, agree the interfaces first, split the work by component, and use Git branches and short daily check-ins.
  • Always compare with a simple baseline and a target. A number alone means little.

Exercises (all in the workbook)

  1. Finalize your project card and your scope list: must have, nice to have, out of scope.
  2. Plan it. Write schedule_check() and make your must-have work fit the calendar, with a 20% buffer.
  3. Agree the interfaces. Write check_pipeline() and describe your components, with one owner each.
  4. Build the thinnest end-to-end version and run the smoke test on at least 10 real inputs. Write down how to run it.
  5. Evaluate it. Write run_capstone_eval(), run your model and a baseline on the same fixed set, and record the results.
  6. Read the failures and write your prioritized next steps.
  7. Stretch: let 5 users try it and summarize what you learn.

Hint ladder

  1. The documentation and a web search for any function you are unsure about.
  2. The written hints under each step in the notebook.
  3. If a self-check fails, read its message: each one names the most likely mistake.
  4. Reference solution: open the solution page only after your own honest attempt.
