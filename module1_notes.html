1. The big picture

Deep learning means learning a function from examples. You show the computer many pictures together with their correct labels. It adjusts a large set of numbers, called weights, until its guesses are mostly right.

In this module the function takes a 28 by 28 picture of a piece of clothing and returns one of 10 classes, such as T-shirt, trouser, or ankle boot. The dataset is called Fashion-MNIST.

The recipe for the whole course: data, then a model, then a loss, then a training loop, then honest evaluation. Every module repeats this recipe with something new plugged in.

2. Data: tensors, datasets, and DataLoaders

A tensor is a block of numbers with a shape, like a spreadsheet that can have more than two dimensions. PyTorch tensors can be moved to a GPU, which does many calculations at the same time. That is why training is fast on a GPU.

One image is a tensor of shape [1, 28, 28]: 1 channel (grayscale), 28 rows, 28 columns. Each pixel is a number between 0 and 1 after ToTensor() converts it.

A Dataset gives you one example at a time. A DataLoader groups examples into batches and shuffles them each epoch.

  • Why batches? Computing on 64 images at once is much faster than one at a time, and it fits in memory. Using all 60,000 at once would not.
  • Why shuffle? If the data is sorted by class, a batch would contain only one class. Shuffling mixes them.

3. The model: a stack of layers

Our model is three simple pieces in a row:

  1. Flatten unrolls the 28 by 28 grid into a list of 784 numbers.
  2. Linear (784 to 128) makes 128 new numbers. Each one is a weighted sum of all 784 inputs plus a bias. Then ReLU sets every negative number to 0.
  3. Linear (128 to 10) makes 10 scores, one per class. The highest score is the prediction. These raw scores are called logits.

How many numbers does the model learn? First layer: 784 x 128 weights plus 128 biases = 100,480. Second layer: 128 x 10 weights plus 10 biases = 1,290. Total: 101,770. Training is the process of finding good values for these 101,770 numbers.

ReLU is what makes the model more than a fancy straight line. You will see exactly why in Module 2.

4. The loss: scoring mistakes

The loss is one number that says how wrong the model is. Lower is better. Training tries to make it small.

For classification we use cross-entropy loss. It looks at the probability the model gave to the correct class:

Probability given to the correct classLoss
0.90 (confident and right)0.105
0.10 (mostly wrong)2.303
0.10 for all 10 classes (pure guessing)2.303
A useful sanity check: with 10 classes, a model that has learned nothing has a loss near 2.3. If your first printed loss is about 2.3 and then falls, training is working. If it starts at 50 or at nan, something is wrong.

In PyTorch, nn.CrossEntropyLoss takes the raw logits directly. Do not add a softmax yourself.

5. The training loop

Training repeats one cycle, over and over, on one batch at a time.

for x, y in train_dl:
    preds = model(x)             # 1. forward pass
    loss = loss_fn(preds, y)     # 2. loss
    optimizer.zero_grad()        # clear gradients from the last step
    loss.backward()              # 3. backward pass: compute gradients
    optimizer.step()             # 4. update the weights
  • Gradient: for every weight, the direction and amount it should change to lower the loss. loss.backward() computes them all. You will write this yourself in Module 2.
  • Why zero_grad()? PyTorch adds new gradients onto old ones. Without clearing, each step would use stale information from earlier batches.
  • Optimizer: the rule for using gradients. Basic gradient descent moves each weight a small step against its gradient. We use Adam, a strong default, with a learning rate of 0.001 (the step size).
  • Epoch: one full pass over the training data. With 60,000 images and batches of 64, one epoch is 938 steps, so 5 epochs is 4,690 weight updates.

6. Evaluating honestly

A model can memorize its training pictures without learning anything general. So we hold back 10,000 images, the test set, that the model never trains on. Accuracy on this set is the fraction of images classified correctly, and it tells you how the model would do on new pictures.

Overfitting means doing well on training data but worse on new data. The sign is a growing gap between training and test results. In Module 3 you will learn ways to fight it.

When evaluating, two small habits matter:

  • model.eval() switches layers like dropout to their testing behaviour. Our model has none yet, but make it a habit.
  • torch.no_grad() turns off gradient tracking, which saves time and memory, because we are only predicting.

8. Common pitfalls

  • Forgetting optimizer.zero_grad(), so the loss behaves strangely.
  • Forgetting .to(device) on the images and labels, which gives a "tensors on different devices" error.
  • Judging the model by training accuracy instead of test accuracy.
  • Wrong layer sizes. The first Linear must take 784 inputs, and the last must output 10.
  • Adding a softmax before CrossEntropyLoss, which already includes it.

9. Check yourself

Try each question first, then open the answer.

Question 1: A batch has shape [64, 1, 28, 28]. How many numbers is that?

64 x 1 x 28 x 28 = 50,176 numbers.

Question 2: Your first printed loss is about 2.3 for this 10-class problem. Is that a problem?

No. A model that guesses randomly among 10 classes has a loss near 2.3, which is exactly what you expect before any learning. It should fall from there.

Question 3: Training accuracy is 99% but test accuracy is 85%. What is happening, and what is your first idea?

The model is overfitting: it has memorized training pictures. Ideas include more data, data augmentation, or regularization such as dropout. You will practise these in Module 3.
