Step 2: evaluate

Weight each batch's mean loss by its size, so the last (smaller) batch does not count too much. model.eval() and torch.no_grad() switch off dropout and gradient tracking.

def evaluate(model, loader, loss_fn, device):
    model.eval()
    total_loss, correct, n = 0.0, 0, 0
    with torch.no_grad():
        for x, y in loader:
            x, y = x.to(device), y.to(device)
            logits = model(x)
            total_loss += loss_fn(logits, y).item() * y.size(0)
            correct += (logits.argmax(1) == y).sum().item()
            n += y.size(0)
    return total_loss / n, correct / n

Step 3: train one epoch

The same five steps as Module 1, plus bookkeeping. model.train() turns dropout on.

def train_one_epoch(model, loader, loss_fn, optimizer, device):
    model.train()
    total_loss, correct, n = 0.0, 0, 0
    for x, y in loader:
        x, y = x.to(device), y.to(device)
        logits = model(x)
        loss = loss_fn(logits, y)
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
        total_loss += loss.item() * y.size(0)
        correct += (logits.argmax(1) == y).sum().item()
        n += y.size(0)
    return total_loss / n, correct / n

Step 4: the full fit() loop

Read it in the order of the flowchart in the lecture notes. The key details: the learning rate is recorded before scheduler.step(); "improved" means strictly lower than the best so far; the counter resets to 0 on every improvement; and the best weights are loaded back at the end.

def fit(model, train_loader, val_loader, loss_fn, optimizer, epochs, device,
        patience=None, ckpt_path="best.pt", scheduler=None, log_fn=None):
    history = {"train_loss": [], "train_acc": [], "val_loss": [], "val_acc": [], "lr": []}
    best_val_loss, best_epoch, bad_epochs = float("inf"), -1, 0
    for epoch in range(epochs):
        tr_loss, tr_acc = train_one_epoch(model, train_loader, loss_fn, optimizer, device)
        va_loss, va_acc = evaluate(model, val_loader, loss_fn, device)
        lr = optimizer.param_groups[0]["lr"]
        if scheduler is not None:
            scheduler.step()

        for key, value in zip(history, [tr_loss, tr_acc, va_loss, va_acc, lr]):
            history[key].append(value)
        if log_fn is not None:
            log_fn(epoch, {key: history[key][-1] for key in history})

        if va_loss < best_val_loss:
            best_val_loss, best_epoch, bad_epochs = va_loss, epoch, 0
            torch.save(model.state_dict(), ckpt_path)
        else:
            bad_epochs += 1
            if patience is not None and bad_epochs >= patience:
                break

    if best_epoch >= 0:
        model.load_state_dict(torch.load(ckpt_path, map_location=device))
    history["best_epoch"] = best_epoch
    history["best_val_loss"] = best_val_loss
    return history

Step 7: run_experiment

Three lines build the model, the optimizer, and the logging function; one call runs fit. The wandb.init and wandb.finish pair around it keeps each run separate in the dashboard.

def run_experiment(config, use_wandb=False):
    set_seed(config.get("seed", 0))
    train_dl, val_dl, _ = make_loaders(config["batch_size"])

    model = make_model(config["hidden"], config["dropout"])
    optimizer = torch.optim.AdamW(model.parameters(), lr=config["lr"], weight_decay=config["weight_decay"])
    log_fn = (lambda epoch, metrics: wandb.log(metrics, step=epoch)) if use_wandb else None

    if use_wandb:
        wandb.init(project="dl-startups-module3", config=config)

    hist = fit(model, train_dl, val_dl, loss_fn, optimizer, epochs=config["epochs"], device=device,
               patience=config["patience"], ckpt_path="run.pt", log_fn=log_fn)

    if use_wandb:
        wandb.finish()

    best = hist["best_epoch"]
    return {"config": config, "val_acc": hist["val_acc"][best], "val_loss": hist["best_val_loss"],
            "best_epoch": best, "history": hist, "model": model}

Stretch: a learning rate scheduler

Cosine annealing lowers the learning rate smoothly toward zero over the run. Build the scheduler after the optimizer and pass it to fit.

optimizer = torch.optim.AdamW(model.parameters(), lr=3e-3, weight_decay=0.01)
scheduler = torch.optim.lr_scheduler.CosineAnnealingLR(optimizer, T_max=15)
hist = fit(model, train_dl, val_dl, loss_fn, optimizer, epochs=15, device=device,
           patience=5, scheduler=scheduler)

Sample answers to the written questions

  • Step 5, when did validation loss stop improving? The printed best epoch tells you, and it is usually early (well before epoch 30). After that, training accuracy keeps climbing toward 100% while validation accuracy stalls or slips. That growing gap is overfitting.
  • Step 6, what changed? With dropout, weight decay and early stopping, the training curve rises more slowly, the validation curve stays closer to it, and training stops soon after the best epoch.
  • Step 8, which setting won and why? Usually a middle learning rate. Too small makes too little progress in 15 epochs, and too large is unstable. The best batch size can differ with the learning rate, because small batches make more, noisier updates per epoch.
  • Step 8, are the top runs really different? Often not. With 2,000 validation images, accuracy has an uncertainty of roughly 0.8 percentage points, so runs within about 1 point of each other cannot be told apart. A fair answer is: "the top three are within noise".
  • Three changes that improved validation score: for example (1) adding dropout, (2) adding weight decay or early stopping, (3) picking a better learning rate from the sweep.

Common mistakes and what they look like

  • Averaging the loss over batches instead of over examples: the evaluate check fails by a small amount, because the last batch is smaller. Multiply each batch loss by its size.
  • Forgetting model.eval() or torch.no_grad() in evaluate: validation metrics are noisy and slower, because dropout is still on and gradients are still tracked.
  • Forgetting model.train() in train_one_epoch: after one evaluation, dropout stays off for training, so regularization quietly does nothing.
  • Saving a checkpoint every epoch: the file holds the last weights, not the best. Save only inside the "improved" branch.
  • Not resetting the counter on improvement: training stops too early. Reset it to 0 whenever validation loss improves.
  • Not loading the best checkpoint at the end: you evaluate the last (overfit) weights. The fit self-check catches this.
  • Recording the learning rate after scheduler.step(): the history is shifted by one epoch.
  • Tuning on the test set: your final number is no longer honest. Use it once, in Step 9.
  • Changing several settings at once in the sweep: you cannot tell what helped. Change one thing at a time.
  • Forgetting wandb.finish() between runs: runs get merged into one confusing chart.
